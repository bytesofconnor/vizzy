2. **Source registry with vector matching.** Build a registry of thousands of official series. Each series has a name, aliases, units, geography, frequency, a license, and a fetch recipe. Seed the registry from the FRED, World Bank, and OWID indexes. Store metadata and embeddings only. Never store the series values in the registry. Fetch those values live when a chart is drawn. Keep any cache of those values short-lived. Match a prompt by meaning to a small set of nearest series. An AI step picks the best match from that set, or it says that none fit. Jev is a possible fit for that step. The web is only a fallback.

   Vizzy stores its app data in Convex. The tables are in `convex/schema.ts`. This repo has no Supabase project. The catalog in `apps/share/lib/connectors/catalog.ts` marks the Postgres connector coming soon. Its blurb says read-only SQL templates. Put the registry in a new Convex table. Search that table with Convex vector search, as Connor suggested. Declare a vector index on that table. The schema does not declare a vector index today. `seriesCache` stores fetched rows. `gatherOfficialSeries` in `apps/share/lib/series.ts` treats a cached row as fresh for one day. That table is the value cache. `matchPrompt` in `packages/resolve/src/catalog.ts` scores aliases on a hand-written list. That list is how a prompt finds a series today.

   The check uses the 20 prompts in `apps/eval/fixtures/source-registry-prompts.json`. Measure catalog-hit rate and correct-series rate on that set before the registry, and measure both rates again after it. The item stays open until those before rates and after rates are recorded. The set includes "US GDP since 2000", "unemployment by US state", "bitcoin 5y", "Minneapolis monthly temp", "housing", "Antarctic sea ice", "renewable share Germany vs France", "S&P 500 20y", "life expectancy Japan/US/Nigeria", "Minneapolis rent", "coffee prices", "top 10 US cities", and eight prompts already written elsewhere on this roadmap.

## Later, after reliability
- CHART.md taste and eval loop — after the Open reliability items are cleared. A machine-readable taste file names chart-type rules, receipt placement, and anti-patterns. Golden evals check charts against that file. The rules live in code, modeled on Vercel DESIGN.md and a code-level design system.
- Personal chart library — a growth bet, not a fix for a chart that fails.
- Edit a published chart at the same URL — the open chart can already be revised. A stable public id is later.
- MCP and a Muse-style host skill — a drop-in Vizzy skill, not a marketplace. It returns a chart URL and a PNG when Muse, or a similar host, calls it mid-task. The chart is a trust signal. `apps/mcp` already lists schema, validate, compile, and publish. More hosts come later.
- Source picking with Jev — optional, and only after retrieval. It arbitrates sources the way a citation check or RAG passage gating does. It does not discover sources. Catalog and matcher fixes that already shipped come first.
- My BI live pins.

- "UI is gone" — the human-readable chart stays. Writers and agents both read that page.
